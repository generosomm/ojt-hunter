## Performance pass (2026-10-23)

Owner reported slow loads. Measured first, then fixed the causes.

| Cause | Fix |
| --- | --- |
| Server functions ran in Washington DC (iad1), database in Singapore: every query crossed the Pacific twice | `vercel.json` regions `sin1` (live `x-vercel-id` now `sin1::sin1`) |
| Config, viewer and stats reads ran 2 to 3 times per page | React `cache()` in `lib/data.ts` and `lib/me.ts` |
| Supabase auth library shipped to every visitor for the sign-in button | imported on click |
| Full motion engine in the first bundle for the hero card | `LazyMotion` + `m`, features loaded after paint |
| Top bar placeholder 64px, real bar 60px: page jumped 4px on some loads (CLS 0.086) | placeholder `h-15` (CLS now 0 to 0.011) |

Full page load (curl, warm): before 1.3 to 3.2 s, after 0.25 to 0.92 s. Cold start after 0.57 to 1.94 s.

Lighthouse mobile (Edge headless, simulated slow 4G), after: home 92 to 98 across 9 runs, role page 96, MOA board 94 to 95; Accessibility and Best Practices 100; unused JS on home 155 KiB down to 61 KiB.
Not 100: Lighthouse's throttled mobile LCP (2.2 to 2.9 s) is mostly render delay (cause not isolated). Home's LCP is the static headline, so the database speedup shows in full load time, not in this score.
Role pages show SEO 91 because Next streams metadata into the body for normal browsers. Checked with curl: `facebookexternalhit` gets description and og tags in the head (share previews work); Googlebot gets them streamed, which Google reads after rendering.

## Job board links and nightly link check (2026-10-24)

Owner reported many apply links opening to "not found". Checked all 38 published links.

- LinkedIn, JobStreet and Prosple refuse automated checks (403/429), so no checker can read them. In a real browser the JobStreet posts checked (Sun Life, DENSO TEN, Exist) were live.
- Dead: Henkel, WTW developer, WTW QA (404), Monde Nissin on JobStreet (404 from a normal connection), Deloitte (page says closed). All five are in the review queue as "post closed"; nothing was closed without review.
- Real-time sync with LinkedIn, JobStreet or Indeed is not possible: no public job search API, and scraping breaks their terms.

Built instead:
- `job_boards` table (public read, admin write): each role page shows "Find it on" search links for LinkedIn, JobStreet, Indeed and Google, searching the short company name plus "intern" (country and legal suffixes like "Philippines" and "Inc." dropped, so boards match). Searches never 404. New boards are rows, not code.
- Nightly check (pg_net + pg_cron in Supabase, 02:00 Manila): `private.start_link_checks()` sends a GET per live apply link, `private.collect_link_checks()` at 02:15 saves `link_status` (ok, dead, blocked) and opens one "post closed" review item per newly dead link. Blocked never counts as dead.
- Role page: a dead link shows "Post link is down" in place of the Apply button; the board links stay.
- The admin has the last word: rejecting a "post closed" item brings the Apply button back, and the checker won't mark that role dead again until the stale window (14 days) passes. A blocked answer never overwrites a dead verdict.
- Second live run (after moving pg_net to the `extensions` schema): 38 sent, 38 answered; 14 ok, 5 dead, 19 blocked. Monde Nissin stayed dead; no duplicate review items.
- The site's own 92 sitemap pages: none show the not-found page.

Tests: `tests/sprints/P7/link_checker.sql` (verdicts, anon and student can't run the checker or add boards, no duplicate review items) ALL PASS; `board-url.test.ts` 3 pass.
