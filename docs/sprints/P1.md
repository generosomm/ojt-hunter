# P1: Database
Status: In progress
Goal: Every table, enum and access rule from the spec exists in Supabase, and the curated seed is imported unpublished.
Scope: schema, RLS, grants, listing view, read helpers, sign-up trigger, curated seed; excludes all UI (P2+).
Depends on: P0

## Decisions
- Companies have `is_published` too, so unreviewed company data, contacts and partnerships stay hidden.
- `dev_exposure` has `low` (little dev but varied) separate from `low_repetitive` (ticket queues, scoring).
- Per-day allowance estimates are computed in the `opportunity_listing` view from `app_config`
  (22 days/month, 8 hours/day), not a stored column, so the numbers are editable without code.
- The HTE list read rule follows `app_config.hte_list_public` (seeded true after FIC approval).
- Public "who" data never leaks: MOA supporter counts and open-check history come from functions
  that return counts and dates only. The two Supabase advisor warnings about them are intentional.
- Admins cannot read other users' private data (profiles, tracker, checklist).
- Admin rows are added once in the SQL editor, never in committed SQL.
